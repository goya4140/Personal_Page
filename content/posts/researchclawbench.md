一个科研智能体能够读论文、运行代码、画出图表，最后交出一份完整报告。但这些产物是否回答了研究问题，是否遵循正确的实验协议，又是否提供了足够证据？ResearchClawBench 将这些问题放进同一套评测：给出研究目标、相关文献和数据，把目标论文留在评价端，再检查系统能独立走到哪里。

本文解读 Wanghan Xu 等人、上海人工智能实验室的 **ResearchClawBench: A Benchmark for End-to-End Autonomous Scientific Research**，依据 [arXiv v5](https://arxiv.org/abs/2606.07591v5)，更新于 2026 年 7 月 3 日。正文结果限定在这一版本；持续更新的项目榜单与论文快照分开理解。

入门时可以先抓住一条线：**给定研究目标与材料 → 自行开展分析 → 提交代码、图表和报告 → 用隐藏参考研究评价证据。** 这里的“独立”发生在已给定目标之下；50 是参照论文水平的评分锚点，21.5 是被测系统的任务平均分，两者都不是完整研究成功率。下文在对应句子旁提供可展开的输入输出说明、评分算例和与 AutoSciRub 的关系。

## 一、课题解读：怎样判断 AI 完成了一项研究

假设我们让 AI 根据气候数据分析雨季推迟的原因。它需要理解研究背景，检查数据中的变量和时间范围，设计分析，运行代码，再解释证据如何支持假设。

一份报告可能语言流畅、图表齐全，却使用了错误时间尺度，遗漏必要的对照，或者把相关关系写成因果机制。这些问题很难通过“有没有输出文件”或“答案是否像论文”来判断。

**端到端科研评测关注的是：系统能否围绕一个科学目标，把数据、实验、证据和结论连续组织起来。** 它既需要检查执行，也需要检查科学判断。

评价的困难在于，研究结果并不只有一种表达方式，也可能存在多条合理路线。完全固定答案，会限制有价值的新方案；完全开放打分，又容易把可信表述误当作可信发现。因此，需要可核验的参照，也需要允许超出参照的空间。

## 二、相关文献解读：从科学代码到论文复现

先认识下面三个直接相关的评测。

| 工作 | 主要测什么 | 与本篇的区别 |
| --- | --- | --- |
| [SciCode](https://arxiv.org/abs/2407.13168) | 把科学问题拆为代码子问题，检查科学知识、推理与程序实现 | 主要评价科学编程，研究流程的范围较小 |
| [ScienceAgentBench](https://arxiv.org/abs/2410.05080) | 从真实研究中提取数据驱动任务，检查生成程序、执行结果和成本 | 聚焦研究工作流中的具体任务，输出统一为程序文件 |
| [PaperBench](https://arxiv.org/abs/2504.01848v3) | 给出目标论文，让智能体实现方法并执行复现实验 | 目标论文对系统可见，重点是按论文完成复现 |

ResearchClawBench 的重点是**隐藏目标论文的再发现任务**：系统获得研究描述、相关文献和数据，需要自行设计与完成分析；评价端则利用目标论文构造评分参照。它覆盖的学科也更广，包括天文、化学、地球科学、能源、信息、生命、材料、数学、神经科学和物理。

这里的“再发现”具有具体边界：研究问题由任务包给出，有些描述还指定方法或目标。因此，它考察的是在已给定科学目标下完成研究的能力，尚未完整涵盖自主选题。[原论文第 2—3 节](https://arxiv.org/html/2606.07591v5#S2)。

## 三、研究问题解读：这套评测想回答什么

下面三个问题是我们的阅读归纳，并非作者逐字列出的研究问题。

1. **怎样构造真实且可执行的研究任务？** 让研究目标、提供的数据与最终评分要求彼此对应。
2. **怎样评价开放的科研产物？** 用目标论文提供参照，同时保留不同路线和更强证据得到认可的可能。
3. **当前系统的困难集中在哪里？** 区分不能执行、偏离问题、证据不足与科学机制缺失，避免只看最终报告是否完整。

相应地，本文的方法重点是任务构建、执行环境和评分机制；实验重点则是整体得分、不同领域的差异，以及失败产物的具体表现。

## 四、方法解读：从真实论文到可检查的研究任务

![ResearchClawBench 的任务、行动空间、系统接入与报告评价流程](../assets/img/blog/researchclawbench/overview.png "图 1 · 左上是任务、文献、数据和专家评分标准；中间是读写、执行与分析；右侧接入现成智能体或 ResearchHarness；下半部分展示代码、产物与报告的连接。评分标准位于评价端。来源：原论文 v5 PDF Figure 2，第 6 页；HTML 对应 Figure 1。原图未改绘，点击查看大图。")

### 第一步：选择目标研究，构造任务包

领域专家选择科学问题明确、数据可获得且有研究价值的论文，提取核心问题，整理相关文献和数据，并围绕论文的关键产物设计评分项。之后进行交叉检查，修正或剔除不合适的任务。

v5 包含 **40 个任务、10 个领域，每个领域 4 个任务**。主要任务类型是诊断分析和目标优化：前者关注机制与解释，后者关注定量目标与性能。

系统实际接收的是[任务描述、相关文献和数据](#reading-note-task-boundary)。**目标论文及由它建立的评分材料留在评价端。** 数据包既包括实验或模拟结果，也包括整理后的特征、后验样本和图表数据；“从原始数据开始”应当按每个任务的具体材料理解。[第 3.1—3.2 节及附录 B](https://arxiv.org/html/2606.07591v5#S3)。

### 第二步：在工具环境中完成研究并提交产物

现成科研或编程智能体通过各自框架执行任务。作者还提供 **ResearchHarness**，用较轻量的 ReAct 循环让模型读取观察、调用工具、执行分析并继续迭代。

它包含网页与学术搜索、文本/PDF/图片读取、文件编辑、Shell 和持续终端等工具，并支持长上下文压缩。因此，论文中的 ResearchHarness 模型结果包含工具环境的帮助，不能解释为模型脱离工具的单次回答能力。

预期产物包括分析代码、中间结果、图表和最终研究报告。论文也明确承认，当前评价主要围绕最终报告展开，尚未对细粒度研究步骤进行完整审计。[第 3.3 节](https://arxiv.org/html/2606.07591v5#S3.SS3)。

### 第三步：把目标论文拆成带权重的科学要求

评分项包含具体标准、技术关键词、权重，以及文本或图像类型。文本项检查研究内容；图像项结合目标图与生成图，检查关键趋势、尺度和证据。

以原文 Table 2 的 **Astronomy_000** 为例，任务从黑洞质量和自旋的后验样本出发，约束超轻玻色子的参数。输入包含两组后验样本，分别有 **10,000** 和 **1,838** 条记录。评分关注以下三件事：

| 科学要求 | 权重 |
| --- | ---: |
| 正确读取并总结质量、自旋后验，明确观测约束 | 20% |
| 对后验样本积分，得到 M33 X-7 的 95% 排除曲线 | 30% |
| 利用排除曲线，推导相关质量范围内自相互作用耦合的上限 | 50% |

这说明，完成数据读取只是研究的一部分；更大的权重放在数据如何支持最终科学约束上。表格来自原论文示例，未将目标论文列表误写成系统可见的输入。

### 第四步：用参考锚定分数衡量证据水平

作者提出 **Reference-Anchored Discovery Score，RADS**。单项在百分制下评价，但把目标论文水平放在中间位置：[50 分锚点与加权总分需要一起理解](#reading-note-rads-example)。

| 分数位置 | 含义 | 解释边界 |
| --- | --- | --- |
| 低于 50 | 相对参考研究，关键证据或分析仍不足 | 可能有局部有效结果，不能一概理解为完全无价值 |
| 50 | 达到目标论文参照下的证据水平 | 是评分锚点，仍然依赖具体标准与评价者 |
| 高于 50 | 评价认为证据、定量结果或机制分析超出参照 | 表示新发现潜力，仍需独立科学验证 |

![RADS 在诊断分析和目标优化中如何定义参考水平与更强证据](../assets/img/blog/researchclawbench/scoring.png "图 2 · 上半部分用机制分析说明证据深度，下半部分用聚合物优化说明定量目标；50 分被设计为参考论文水平。这里是评分机制示意，不能当作系统已经完成新发现的实验结果。来源：原论文 v5 PDF Figure 4，第 9 页；HTML 对应 Figure 3。原图未改绘，点击查看大图。")

论文报告由 **GPT-5.1** 在运行结束后按 rubric 评价报告。这是专家构建标准、模型执行打分的评价，不能等同于每份报告都经过领域专家盲评。[第 3.4、4.1 节](https://arxiv.org/html/2606.07591v5#S3.SS4)。

作为实现补充，我们核对了[官方评分器的固定版本](https://github.com/InternScience/ResearchClawBench/blob/c19a320d3d3d40e370e59001cc219794c4261055/evaluation/score.py)：它按评分项给出分数，再计算 `总分 = Σ(权重 × 单项分数) / Σ权重`。这个代码快照帮助解释汇总方式；它不是论文全部历史运行环境的复现证明。

联系刚读过的 [AutoSciRub](autoscirub.html)：ResearchClawBench 在评价端用专家构建的要求检查产物，后续的 AutoSciRub 则根据可见任务材料自动生成执行准则，并用它指导修订。[两者的 rubric 来源、可见范围和作用不同](#reading-note-autoscirub-connection)。把它们连起来，有助于区分“怎样衡量研究”与“怎样帮助系统做好研究”。

## 五、实验设计与结果：完整报告距离可靠研究还有多远

### 主实验：智能体与 ResearchHarness 模型的整体表现

论文比较 **7 类智能体**和 **17 个通过 ResearchHarness 执行任务的模型**，均使用上述 40 个任务。Table 5 还单列两个 EvoScientist 版本，因此智能体部分实际有 **8 个配置行**。下列数字是任务平均 rubric 分数，分数越高越好。

| 智能体配置 | 底层模型 | 平均分 |
| --- | --- | ---: |
| Claude Code | Claude-Opus-4.6 | 21.5 |
| EvoScientist v0.1.1 | GPT-5.4 | 18.8 |
| Codex CLI | GPT-5.4 | 18.4 |
| OpenClaw | GPT-5.4 | 16.6 |
| ResearchClaw | GPT-5.4 | 16.3 |
| EvoScientist v0.0.4 | GPT-5.4 | 15.5 |
| ARIS Codex | Codex / GPT-5.4 | 13.6 |
| Nanobot | GPT-5.4 | 12.8 |

*来源：原论文 v5 Table 5，PDF 第 10 页。*

ResearchHarness 的前五个模型结果如下；完整模型列表见原表。

| ResearchHarness 模型 | 平均分 |
| --- | ---: |
| Claude-Opus-4.7 | 20.7 |
| Claude-Opus-4.6 | 19.9 |
| Qwen3.7-Max | 18.7 |
| GLM-5.1 | 18.2 |
| Qwen3.6-Plus | 18.0 |
| Kimi-K2.6 | 18.0 |

*第五名分数存在并列，因此列出六行。来源同上。*

最直接的结论是：**在这套任务和评分标准下，各系统的平均产出距离 50 分参照仍有明显差距。** 21.5 是平均分，不能写成“成功完成了 21.5% 的科研任务”。均值低于参照，也不表示每一道题都低于参照。

总体排名还掩盖了任务差异。Claude Code 在 40 个任务中仅有 12 个任务取得最佳结果；模型组的不同领域也由不同模型领先。例如 Claude-Opus-4.6 在天文、地球、能源和数学领先，GLM-5.1 在化学领先，Qwen3.7-Max 在物理领先。[第 4.1—4.2 节及 Table 5](https://arxiv.org/html/2606.07591v5#S4)。

比较框架作用时也需保留底层模型差异。Claude Code 使用 Claude-Opus-4.6，多数其他智能体使用 GPT-5.4；它们的差距包含模型与框架共同作用。正文虽然称统一协议，但未完整列出逐系统硬件、token 上限和运行预算，无法据此得出严格同等成本下的框架排名。

### 补充分析一：逐题最优与报告质量分别说明什么

作者还计算了 **frontier mean**：对每个任务，事后选出所有被测系统中的最高分，再对任务求平均。它表示已有结果的组合上界，实际部署时并没有一个已知选择器能够提前挑中每题赢家，也不是某个系统多次尝试的平均值。

v5 引言的智能体 frontier mean 为 **24.6**，第 4.2 节则为 **25.8**。我们按附录 Table 8 的逐任务表复算：排除新增 EvoScientist v0.1.1 时约为 **24.56**，包含全部八个配置时约为 **25.84**，分别对应这两个舍入值。模型组的 frontier mean 报告为 **26.5**。因此，这里的差异应保留配置范围说明，不能混为同一统计口径。

报告外观与科学证据也需要分开看。Table 6 的四个补充维度为全面性、深度、指令遵循和专业性；这里摘录三组：

| 智能体 | 主 rubric 分数 | 深度 | 专业性 |
| --- | ---: | ---: | ---: |
| Claude Code | 21.5 | 58.0 | 76.4 |
| Codex CLI | 18.4 | 65.9 | 74.4 |
| ResearchClaw | 16.3 | 62.2 | 74.8 |

*来源：Tables 5—6。补充维度与主 rubric 的评分对象和锚点不同，不能用两列相减来衡量差距。*

这些结果支持：报告可以有较好的专业表达，而关键科学证据仍不足。Table 6 使用的是原七类智能体，其中 EvoScientist 为 v0.0.4，未覆盖新增版本。[第 4.3 节](https://arxiv.org/html/2606.07591v5#S4.SS3)。

### 补充分析二：更高成本是否带来更好的研究

作者比较各系统的平均费用、耗时与分数，并画出资源—分数的 Pareto 前沿，即当前结果中难以同时改善成本和分数的配置。

资源投入与得分总体有正关联，但这属于不同系统之间的观察比较。它不能单独证明增加同一系统的预算就会改善研究，也不能证明额外计算必然无效。模型能力、工具框架和停止策略都可能同时变化。[第 4.4 节](https://arxiv.org/html/2606.07591v5#S4.SS4)。

本文没有提供隔离单个组件贡献的系统性消融；上述结果主要是系统对比与行为分析。

### 补充分析三：失败主要发生在什么地方

作者分析原七类智能体在 40 个任务上的 **280 次运行**，把错误分成六类。

![ResearchClawBench 的六类错误及对应的任务实例](../assets/img/blog/researchclawbench/errors.png "图 3 · 主要问题集中在实验设计不匹配、证据不匹配和科学核心缺失。各项图示比例不能相加解释为互斥分布；论文未给出逐项原始计数。下方每列给出预期产物、实际产物和差异。来源：原论文 v5 PDF Figure 6，第 11 页；HTML 对应 Figure 5。原图未改绘，点击查看大图。")

前三类最能说明这套评测关注什么：

- **实验设计不匹配：** 原本需要检验长期天气预测与指定基线，系统改做短期持续性或线性外推分析。代码可以运行，却换了实验协议。
- **证据不匹配：** 数字、图表或结论与关键证据不一致。
- **科学核心缺失：** 报告使用了相关领域的术语和工具，却没有实现或验证目标机制。

另外三类是目标偏移、可靠性或报告失败，以及执行失败。作者的分析支持：问题常常发生在已经完成了一些工作之后，系统逐步偏离了应当验证的科学要求。[第 4.5 节](https://arxiv.org/html/2606.07591v5#S4.SS5)。

**Physics_002** 提供了一个具体例子。OpenClaw 得到论文报告的 27.45 分，并恢复了量子电路保真度随深度下降的直接趋势，但遗漏了多估计器一致性、镜像电路推断和门计数误差模型。直接趋势只是完整证据链的一部分。

这组案例也有数值呈现问题：原图五项权重合计为 **105%**，而当前官方评分器会按权重总和归一化，因此不能用该图严格复现 27.45 的归一化总分。原文把分项写为 47/50、40/50；结合 RADS 定义，应理解为接近 50 分参考锚点，不能把 50 当作百分制满分。这里保留作者报告值，仅用案例解释缺失的验证步骤。[第 4.6 节](https://arxiv.org/html/2606.07591v5#S4.SS6)。

## 六、我们自己的思考

### 课题思考：这个领域在研究什么

科研智能体评测的关键，是让“完成研究”变成可以逐项核对的主张。运行代码、生成图表和写成报告，都需要回到科学目标，检查它们究竟支持了什么。

这篇论文的价值在于，把目标论文的关键产物作为评价参照，同时尝试容纳更强的证据。它让我们看到，科研流程的完整性与科学证据的充分性，需要分别检查。

### 局限问题思考：目前还存在哪些问题

**第一，参考论文会影响评价边界。** 某项方案偏离参考，可能是犯错，也可能是一条合理的新路线。高于参考的模型评分，同样需要独立科学验证；论文也承认，真正新发现需要更可靠的评价方式。

**第二，最终报告不能完全证明研究过程。** 当前评分以报告和图像为主，代码执行、数据来源、指标计算及结论之间，还需要更细的审计。论文没有报告足够的人类—模型评分校准和跨评价器稳定性结果，来消除这些不确定性。

**第三，任务与运行覆盖仍有限。** 每领域只有四个论文任务，且主要是基于已有材料的计算研究，不能代表整门学科或真实湿实验能力。重复运行方差、严格预算对齐及目标论文泄漏风险也需要进一步检验；“任务包不提供目标论文”本身，无法排除预训练记忆或外部检索中的接触。

**第四，版本和统计口径影响可复现性。** 新旧 EvoScientist 配置、不同 frontier 范围、图号与案例权重存在更新不一致。项目还在发展，评价需要固定论文、数据、评分器和系统版本。[原论文第 6 节](https://arxiv.org/html/2606.07591v5#S6)。

### 解决方案思考：这些问题有哪些解决方向

下面是我们提出的后续方向，与上述问题逐项对应。

1. **为不同研究路线提供独立验证。** 让领域专家盲评偏离参考的方案，检查其科学目标、有效性和新颖性；对声称超出参考的结果增加重复实验或外部数据验证。
2. **把评分绑定到可追溯产物。** 将每项主张对应到输入数据、代码版本、命令、日志、指标和图表；对高权重要求进行独立重放，并比较多评价器与专家判断的一致性。
3. **扩展任务并控制比较条件。** 增加每领域任务与重复运行，报告置信区间；在固定模型下比较框架、在固定框架下比较模型，同时测试文献泄漏、数据污染和接入真实实验反馈后的表现。
4. **发布可复算的评测快照。** 固定数据与代码提交、配置列表和运行结果，自动计算均值、逐题最优与权重归一化，并检查正文、图表和榜单是否使用同一统计范围。
