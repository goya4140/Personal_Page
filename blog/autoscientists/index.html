AutoScientists：科研智能体怎样组队，决定下一次实验

从共享实验日志、提案互评和停滞后改组，理解自组织团队在相同实验资源下如何搜索，以及试验次数与实际耗时的区别。

如果九个科研 Agent 共享一组算力，它们应该各自尝试，还是先交流再决定跑什么？AutoScientists 把这道题变成了一个实验：让智能体共享结果、在开跑前互评提案，并在搜索停滞时重新组队。在 BioML-Bench 上，这套系统把平均榜单百分位从单 Agent 对照的 66.07 提高到 74.40。GPT 实验则显示，到达同一个验证指标需要的试验更少。两组对照匹配了实验资源，但多 Agent 系统用了更多 LLM token。原论文第 4–5 节

本文依据 Shanghua Gao、Ada Fang 和 Marinka Zitnik 于 2026 年 11 月 10 日修订的 arXiv v2。

一、课题解读：长程实验怎样分配下一次尝试

设想一组研究者要在有限预算内改进图像分类模型。团队可以试数据增强、换网络结构，也可以改优化器。连续几次调整增强参数都没有收益时，值得问的是：该继续细调，还是把下一次训练留给另一条路线？如果另一位成员已经试过类似配置，先读他的实验记录就可能省下一次训练。

长程计算实验的难点在于，哪些方向值得探索，会随新结果而改变。系统要维持多个候选方向，同时让失败和成功都能影响下一轮资源分配。几次小幅改进也需要重新核验，因为训练随机性可能让一次偶然高分变成整个团队接下来使用的基线。

三、研究问题解读：组织方式能改善哪些结果

按论文的实验安排，我们把问题归纳为三项：

  1. 相近的实验资源下，自组织团队能否训练出表现更好的模型，并用更少的试验达到同一验证目标？
  2. 当起点已经是一套表现较强的程序时，多条研究路线能否继续找到有效修改？
  3. 分析员、互评、重新组队和共享实验记录各有什么作用？哪些证据能区分它们的贡献？论文第 4 节及附录 B

四、方法解读：智能体如何围绕实验结果重新组队

第一步，讨论方向并形成团队。 输入包含任务、数据、评价协议，以及可选的起始代码。各 Agent 阅读当前最优程序和论坛记录，提出并评议方向。讨论末尾由该轮最后一位 Agent 汇总名单，之后各 Agent 在下一次周期性唤醒时读取名单。可用的 Agent 数量在启动前设定，论文默认 3 个分析员、6 个实验 Agent。确定性的监控程序负责唤醒，方向和成员分工由 Agent 讨论形成。论文第 3.2、4.1 节与附录 A

第二步，用共享状态选择实验。 分析员读实验日志，把未充分探索的方向和具体提案写进团队队列。实验 Agent 认领提案，修改当前最佳程序、训练并写回指标。共享状态保存当前最佳程序、实验日志、论坛、队列和失败记录。其他团队可以据此检查重复提案、质疑实验设计，也可以借用一条有效方向。评论与日志让队伍即使分开工作，也能看到彼此的证据。论文第 3.2 节与附录 A.4–A.7

第三步，核验小幅改进，停滞时重新分工。 作者用重复种子估计同一程序的波动范围。候选改善大于设定噪声带时可直接更新最佳程序。小幅改善在第二个随机种子上也优于当前最佳，才获保留。论文用最近约 10 次实验未改善作为停滞示例。团队可以重开讨论，提议合并、拆分或调整研究方向，调整需要受影响团队认可。最终交付最佳程序、模型卡和研究发现报告，实验日志保留探索过程。论文第 3.2 节与附录 A.6

五、实验设计与结果：相同实验预算能推进多少

主实验一：BioML-Bench 的模型表现

24 个任务覆盖生物医学影像（4）、药物发现（9）、蛋白质工程（6）和单细胞组学（5）。主要对照 Autoresearch 与 AutoScientists 使用同一个 Claude Code / Claude Sonnet 4.6 后端。两者每任务用 1 张 H100，影像任务给 16 小时，其余给 4 小时。部分其他基线的影像结果沿用原基准报告，其余对应任务重新运行。影像、药物与单细胞按保留测试集评价，蛋白质工程按基准的交叉验证协议评分。论文第 4.1–4.2 节及附录 F.1

任务组 Autoresearch 平均百分位 AutoScientists 平均百分位
全部（24） 66.07 74.40
生物医学影像（4） 39.60 45.75
药物发现（9） 46.16 64.52
蛋白质工程（6） 96.97 96.97
单细胞组学（5） 86.00 88.00

全体任务平均提高 8.33 个百分点。药物发现的差距最大，蛋白质工程两者持平。AutoScientists 完成了 24/24 个任务，其中 75.0% 超过公开榜单中位数。74.40 是平均榜单百分位，完成率和超过中位数的比例各有单独定义。由于每任务只有一张 GPU，BioML-Bench 上的训练顺序执行，结果主要反映团队如何选择接下来跑什么。论文图 3、表 1 与第 5 节

主实验二：GPT 训练优化需要多少次试验

每次试验在一张 H100 上训练 5 分钟，反复使用验证集 bits per byte（val_bpb，越低越好）指导搜索。两组从同一程序出发时，AutoScientists 用 34 次达到约 0.978，Autoresearch 用 65 次。文中的 1.9 倍由实验次数之比得来。固定为 50 次时，双方分别达到 0.9777 和 0.9790。论文图 4 与附录表 S2

两组再从同一个 0.9777 的较强程序和同一份失败记录起跑，AutoScientists 在 93 次中接受 7 次改进，最终到 0.9730。Autoresearch 在 100 次中接受 0 次，保留起点。这里的得分来自搜索过程中反复查询的验证集。另一个多 GPU 实验固定团队，只改变 GPU 数量，把每次实验的实测耗时从 9.7 分钟（1 张）降到 4.4 分钟（4 张）。它回答的是并行硬件能节省多少时间。论文第 4.3 节与附录 B.3

主实验三：ProteinGym 上的方法迁移

作者从已有的 Kermut 方法出发，在一个开发测定上搜索，随后冻结所获得的方法，按官方协议在 217 项测定上评估。作者报告平均 Spearman 相关系数从 0.657 升至 0.700，即绝对提高 0.043、相对提高约 6.5%。同时，MSE 增加了 0.006。这个结果展示了排序质量的提高，同时揭示了排序与数值预测误差之间的取舍。217 项汇总包含开发测定。实验报告的是计算基准上的预测表现。论文第 4.4 节与表 2

消融：不同任务依赖不同协作环节

在表 3 的四个代表任务中，完整配置的主指标都最好。去掉分析员时，TDC-hERG 的 AUROC 从 0.867 降到 0.738。固定队伍时，GPT 验证损失从 0.9777 升到 0.9833。附录进一步保留初始自组织、只禁止中途改组，结果为 0.9806。当初始队伍也与完整配置一致但仍禁止改组时，结果为 0.9794。这两个补充对照把初始分工与中途改组拆开。附录 D 的完整轨迹与消融轨迹长度不同，末端值应结合运行预算解读。独立 Agent 对照同时去掉反馈与共享状态，因此它的差值包含两类改动。论文表 3 与附录 B.2、D

六、我们自己的思考

课题思考：这个领域在研究什么

这项工作把科研 Agent 的一个具体决策变成了可以对照的实验：下一笔计算预算该投到哪个假设上？ 当日志能跨团队流动时，一次失败也可能改变其他成员的选择。与 EvoScientist 一起读，可以看到两种时间尺度：AutoScientists 考察一次搜索中如何使用刚得到的反馈，EvoScientist 则把经验保存到下一项研究。

局限问题思考：目前还存在哪些问题

实验预算和总成本是两种账。 主对照匹配训练硬件与计算窗口，讨论、互评和改组消耗的 LLM token 更高。反复优化验证指标会改变证据的含义。 GPT 的改进来自搜索用的验证集，单个最佳点也可能受种子和搜索轨迹影响。消融的结论依赖任务和配置。 论文提供了补充对照和部分独立运行，仍需更多配对重复来判断哪种条件下改组值得付出协调成本。论文第 5 节及附录 C、D、F

解决方案思考：这些问题有哪些解决方向

可以用相同底模和起点按两种预算各做一次对照：一组匹配 GPU 时间，另一组匹配 GPU 与 LLM 的总成本，同时报告达到目标所需的试验次数与耗时。搜索期间保留独立的最终测试集，用预先规定的种子复核冠军程序。最后，用相同初始队伍配对比较「允许改组」和「固定队伍」，记录每次改组前后的重复试验率与收益，检验改组是否把预算转移到了更有产出的方向。
