Evo-Harness：Agent 怎样把失败轨迹编成可复用技能

从失败反思、候选经验到技能库更新，解读五项主实验、训练集技能迁移、在线更新和反馈消融。

一个 Agent 在上次任务中失败了，它该把整段日志留给下一次任务，还是从中提炼一条可以直接执行的检查规则？Evo-Harness 把这一步称为「从上下文到 Harness 的技能编译」：任务完成后，从失败轨迹提取候选经验，再由另一个环节决定哪些经验应加入、合并、修改或舍弃。底层模型固定，变化发生在随任务批次更新的外部技能库中。原论文 v2，Tianxin Wei 等

一、课题解读：一次失败能留下什么

假设一个数据分析 Agent 生成了统计表，却遗漏了某个分组。把整份原始日志存起来，可以帮助回看这次错误，但下次的文件名、字段和任务目的可能都不同。更容易复用的做法是记录触发条件和检查动作：任务要求按组交付时，提交前核对输入中出现的分组是否都在结果中。

困难在于从有限证据里判断范围。某个遗漏可能来自数据读取、分组定义或输出格式。把一次局部错误改写成适用于所有任务的规则，可能给其他任务添麻烦。评估这类方法要看早期任务产生的经验，能否帮助之后遇到的任务。

三、研究问题解读：学习规则怎样影响下一批任务

论文第 4 节检验四个问题：固定求解模型时，更新 Harness 能否提高整体通过率？通用规则与主题流程各贡献多少？训练集上生成的技能能否跨任务、跨模型使用？环境反馈和模型自评给更新带来什么差别？

这里的 Harness 指受预算约束、能被检索并注入提示词的外部行为指南。实验中的技能用自然语言表示，「编译」指把 包含噪声的过程记录整理成更短、更有适用条件的规则。论文第 3–4 节

四、方法解读：求解、反思、整理，再用于下一批

第一步，检索当前技能，完成本批任务。 求解器按任务挑选相关条目并注入上下文，执行后留下任务指令、动作轨迹、结果和可获得的反馈。默认每批 16 道题，批内使用当前版本，更新后的指南用于后续批次。附录 F 报告，技能选择使用 Claude Sonnet 4.5，通用技能库和每个主题各设 5 条上限。论文第 3.1 节与附录 F

第二步，反思失败，形成候选经验。 任务失败或收到负反馈后，求解侧从原始上下文提炼四项内容：教训、触发条件、支持证据和适用范围提示。这个阶段聚焦当前轨迹，已有指南的查重和冲突处理留给后一阶段。比如，环境确认结果少了一个分组，反思可以记录该缺口和检查方式。论文第 3.2 节

第三步，整理候选并更新技能。 更新器（evolver）同时读取本批候选和现有指南，决定新增、合并、修订或跳过。能覆盖多个任务的模式写入通用技能。依赖某类任务接口或局部规则的做法保留为主题流程。更新器处理的是指导内容，求解器仍使用原模型权重。论文把求解器、更新器与反馈源拆开，以便分别做对照。论文第 3.2–3.4 节

补充实验：两种迁移口径

SWE-bench Lite 的迁移实验使用 Opus 4.7 求解、Sonnet 4.5 生成技能。无更新为 68.8%。在训练集形成技能、再拿到测试集用，达到 73.4%。在测试任务流中根据先前任务的反馈继续更新，达到 75.0%。前一项检验训练所得规则的迁移，后一项允许使用前面测试任务的反馈，衡量在线适应。另一个模型搭配实验中，Sonnet 4.5 做求解器时，两种演化配置均低于它自己的无演化对照，说明得到规则之后，求解器是否会使用同样重要。论文第 4.5 节、图 5–6

六、我们自己的思考

课题思考：这个领域在研究什么

这篇论文把「记住失败」细化为两个可检查的决定：从轨迹里抽取哪条经验，以及这条经验应该进入哪一层指南。短小的适用条件和验收动作，可以让我们检查某次提升是否与模型执行规则有关，也可以追查错误指导来自哪次更新。

局限问题思考：目前还存在哪些问题

主实验覆盖文本和工具环境中的单 Agent，外部评估信号在研究现场未必及时可得。在线表现还可能随任务顺序、批大小和早期反馈而变化。总通过率能比较系统配置，要判断哪条技能产生了效果，还需要将具体注入内容和动作变化配对核对。论文也将可执行代码技能和多 Agent 系统留在评估范围之外。论文 Limitations

解决方案思考：这些问题有哪些解决方向

可以对同一组任务随机排列多次，报告早期与后期通过率、技能入库后的错误率和额外模型成本。保留冻结迁移和在线更新两组，并记录每题注入了哪条技能。在数据分析场景中，可用独立验证器给出分组覆盖、参数生效或文件一致性信号，再逐条关闭技能检查，估计收益来自哪一步。
